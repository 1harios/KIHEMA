# Резервный сайт без собственного домена

Адрес: https://kihema.93-123-84-128.sslip.io

Это самостоятельная SvelteKit Node-копия сайта на VPS 93.123.84.128, а не
перенаправление или прокси к Vercel. Основной https://kihema.vercel.app остаётся.
sslip.io — внешний DNS-сервис с адресом на основе IP. Покупать домен не нужно;
при смене IP потребуется изменить адрес и настройки. Собственный домен позже
можно добавить в Caddy и `ORIGIN`.

## Устройство

- Caddy выдаёт и продлевает HTTPS-сертификат, проксирует сайт в `127.0.0.1:3000`.
- Страницы и JSON сжимаются gzip/zstd; видеосегменты не пережимаются.
- `kihema-web.service` запускает Node 22 от пользователя `kihema`, автоматически
  перезапускается и запускается после перезагрузки VPS.
- `/party` проксируется в существующий сервер комнат `127.0.0.1:8092`.
  `/party/КОД` остаётся страницей приглашения. Комнаты общие с основным сайтом.
- Видео идёт с `video.93-123-84-128.sslip.io`. CORS разрешён только двум
  опубликованным сайтам; приватный API TorrServer по-прежнему требует ключ.
- Настройки: `/etc/kihema/web.env`, владелец root, права `0600`.
- Выпуски: `/opt/kihema/web/releases/`; активный — symlink
  `/opt/kihema/web/current`. Данные — `/var/lib/kihema/web`.
- Node слушает только loopback. Дополнительные публичные порты не нужны.

## Сборка и обновление

```sh
npm ci
npm run check
npm run build:vps
```

Последняя строка сборки выводит путь к `release.tar.gz` во временной папке.
Архив содержит Node-сборку и production-зависимости из lockfile; `.env`, ключи,
локальные базы, `.vercel` и инструменты сборки в него не входят.

Первичная установка с авторизованным SSH-ключом:

```sh
node scripts/deploy-vps.mjs /absolute/path/release.tar.gz /absolute/path/ssh-key
```

Скрипт использует локальные приватные TMDB-настройки, передаёт их по SSH stdin,
проверяет Caddy и Node, сохраняет старые настройки в `/etc/kihema/backups`,
подключает новый выпуск и включает автозапуск. При ошибке установки возвращает
прежние файлы и выпуск. SSH-пароли/ключи в репозиторий не записываются.
При обновлении сохраняется существующий `SESSION_SECRET`, а сервер комнат
перезапускается только при изменении его кода.

На VPS нужен Node 22. Перед обновлением сохранить текущую цель `current`,
распаковать архив в **новую** папку выпуска и запустить его с production-env.
Затем атомарно заменить `current` и перезапустить `kihema-web`.
Не перезаписывать активный выпуск во время работы процесса. Предыдущий выпуск
сохранять для отката: вернуть symlink и перезапустить сервис.

Шаблоны systemd/Caddy и перечень переменных находятся в `deploy/vps/`.
`SESSION_SECRET` — случайное production-значение, TMDB-ключ — из приватного
окружения проекта, `TORRSERVER_API_KEY` — тот же секрет, что у Caddy.
Не устанавливать `DEMO_MODE=true`. Production Node **не** загружает `.env`
автоматически: переменные задаёт systemd через `EnvironmentFile`.

Перед заменой Caddyfile выполнить `caddy validate` с окружением Caddy.
Использовать `systemctl reload caddy`, чтобы не прерывать существующие видео.
Перезапуск `kihema-party` разрывает текущие WS-подключения и очищает комнаты;
изменения его origin-списка следует устанавливать в период без просмотров.

## Ограничения резерва

Резерв устраняет зависимость **страниц и API** от Vercel, но использует тот же
VPS для видео и комнат, внешние TMDB/поисковые сервисы и DNS sslip.io. Это не
резерв от отказа самого VPS или блокировки его IP у провайдера.
Проверка из России у проблемного оператора всё равно необходима.
История просмотров, избранное и другие browser-local данные раздельные для
двух адресов; автоматического переноса аккаунтов/localStorage нет.
